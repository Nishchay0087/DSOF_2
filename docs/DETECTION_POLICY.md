# Detection and response policy

Only Collector's internal real-packet callback can enter the trusted capture pipeline. Packets are keyed into bounded bidirectional flows and independently reassembled for cleartext HTTP/1 requests. A flow is finalized at idle timeout, maximum age/packet count, eviction or shutdown. Default idle delay is two seconds. Continuous flows can take up to the maximum duration to finalize; this is not instant inline blocking.

The flow extractor supplies every documented feature in the supplied order. The original model predicts once per completed flow and returns its own class/probabilities. Missing or malformed features fail ML inference; HTTP rules remain usable. Model readiness means the artifact loaded and passed structural validation, not that its missing training contract was reconstructed. Raw live features and labels follow explicitly documented assumptions.

An ML decision is suspicious when its class is not `Normal Traffic` and its own predicted-class probability reaches `DSOF_ML_THRESHOLD` (default 0.90). This is a configurable policy cutoff, not a calibrated probability of attack. HTTP SQLi/XSS/traversal indicators trigger independently of this cutoff. `both` means both branches independently qualified. Overall category is `Web Attacks` when an HTTP rule matches, otherwise the qualifying ML class. ML outputs are never rewritten. Rule evidence establishes an attempted suspicious request, not exploit success.

All complete flows persist, including benign or unavailable-ML outcomes. A qualifying flow produces one UUID-derived alert. Early repeated finalization returns without rewriting evidence, origin or counters. Reassembly deduplicates identical retransmissions; repeated genuinely new connections remain distinct evidence. Rule matches are deduplicated and limited to 16 per alert. Request inspection limitations are separately retained. Conflicting later overlaps mark a stream ambiguous; earlier complete observed requests remain evidence with that limitation. No generic HTTP response, cookie or referer signature is treated as proof of attack.

The alert is stored before orchestration. `config.policy.json` maps supported attack categories to `web`, `ssh`, `database`. Defaults map Web Attacks to web, Brute Force to SSH-style, and Bots/DDoS/DoS/Port Scanning to the web observation service. The last mapping is a safe observation fallback, not an assertion that every category is an HTTP attack or that it will engage with the emulator. Brute Force at database destination ports 1433, 1521, 3306 or 5432 selects the database-style emulator. Mapping configuration is validated on startup.

The orchestrator is idempotent per service kind; it records requested/starting, performs atomic bind/listen and a real authenticated health probe, then records listening. Resource limits, cooldowns and failures are explicit. Existing sessions/alerts do not imply the same attacker. No proxy, NAT, firewall rule, redirection or host command execution is implemented. Only actual subsequent service connections yield sessions. A deployment with no session has no DSI.

Live capture, authenticated fresh manual tests, and dataset replay remain distinct origins. Historical records retain original origin and runtime ID. Model-only manual requests cannot forge alerts. Fresh-test metadata comes from captured requests plus local authenticated registration, not a public API claim of detector evidence.
